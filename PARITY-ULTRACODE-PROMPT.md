# Промпт для ultracode: свести разницу macOS ↔ Windows к нулю

Скопируй всё, что ниже разделителя, в новую сессию Claude Code (в корне `/Users/ilia/Documents/Rimeo`),
дописав в начало слово `ultracode`.

---

ultracode

Задача: довести Windows-агент Rimeo до полного паритета с macOS-агентом. Матрица различий —
`RimeoAgent/PARITY.md`, она актуальна на build 254 и является источником правды. Прочитай её первой.

## Что это за проект

- `RimeoAgent/macos_arm64/` — macOS-агент (Swift, SwiftPM). **Эталон.**
- `RimeoAgent/windows_csharp/` — Windows-агент (C#, WinUI). **Отстаёт.**
- `Rimeo/` — iOS-приложение (SwiftUI). Ходит к агенту по LAN напрямую либо через облако (WS-relay).
- `rimeo_webapp/` — Flask-облако (rimeo.app). ЖИВОЙ ПРОД, деплой руками через scp.
- iOS общается с ОБЕИМИ платформами одним и тем же API. Поэтому любое расхождение в контракте
  агентов — это баг, который видит пользователь.

## Главное правило этой задачи

**Windows должен отвечать на те же запросы тем же контрактом.** Не «похоже», а «так же»: те же пути,
те же поля в JSON, те же коды ошибок. iOS не должен знать, на какой платформе крутится агент.

## Что нужно сделать (по убыванию боли)

### 1. Рекомендации — их на Windows НЕТ ВООБЩЕ

`POST /api/playlist/recommendations` на Windows не существует: `RecommendForPlaylist` не реализован,
эндпоинт не отвечает. То есть у пользователя Windows блок «Recommended» в приложении просто пустой.

Портировать с macOS (`RimeoAgent/macos_arm64/Sources/RimeoAgentMac/Services/`):

- `KeyNormalizer.swift` — тональность в трёх нотациях. В библиотеках Rekordbox ~46% треков хранят
  ключ классически (`Am`, `C#m`), а не в Camelot (`9A`), плюс энгармоника (`C#m` == `Dbm` == `12A`).
  Windows-парсер понимает только Camelot ⇒ гармонический фильтр молча выключен на половине библиотеки.
- `GenreCanon.swift` — 60 сырых написаний жанра → ~8 корзин (включая кириллический `Хаус`).
- `CoPlayGraph.swift` — **сердце новых рекомендаций.** Граф совместности: соседние треки в реальных
  сессиях истории (окно ±2, сессии короче 10 треков отброшены — Rekordbox сам фрагментирует историю)
  плюс co-occurrence по ручным плейлистам. ⚠️ Smart-плейлисты ИСКЛЮЧАТЬ: они порождены правилом
  («genre = Afro House»), учиться на них — переучивать модель на тот же жанровый фильтр.
  Нормировка косинусом + shrinkage, иначе трек, который играется в каждом сете, становится
  «похожим на всё».
- `TrackIdentity.swift` — дедуп по «артист + название»: та же запись, ре-импортированная под другим ID
  (`.wav` и `.aiff` копии одного трека), не должна предлагаться в плейлист, где она уже лежит.
  ⚠️ Разные ремиксы одной песни — РАЗНЫЕ треки, схлопывать их нельзя.
- `TrackAvailability.swift` — не рекомендовать треки, файлов которых нет на диске.
  ⚠️ Критично: битый трек никогда не игрался ⇒ он идеальный кандидат в квоту «открытий».
- `SimilarityEngine.swift` — новое ранжирование. **BPM теперь ГЕЙТ (±3 BPM, с half/double-time),
  а НЕ тай-брейк.** Причина: в реальной DJ-библиотеке 75% треков лежат в окне 118–130 BPM —
  «близкий BPM» не различает ничего, и сортировка по нему давала случайную выдачу.
  Основной вклад в скор — совместность, метаданные вспомогательные.
  Квота: ≥3 непроигранных трека в каждой десятке (иначе блок «что добавить» предлагает только то,
  что человек и так играет — а не игралось у людей ~47% библиотеки).
  Пагинация: `offset` в теле запроса → Refresh отдаёт следующую страницу, а не тот же топ.

Контракт: `POST /api/playlist/recommendations {track_ids[], limit, use_key, exclude_ids[], offset}`
→ `{results:[{track,score}]}`. Проверь по `macos_arm64/.../HTTPServer/APIRouter.swift`.

Windows-`/api/similar` сейчас — **другой, старый движок** (свои веса, свои поля score). Его надо
заменить на портированный, а не оставлять рядом: iOS декодирует одни и те же поля.

### 2. Порядок плейлистов (`Seq`)

macOS читает `djmdPlaylist.Seq` и отдаёт настоящий порядок Rekordbox. Windows — нет, там алфавит.
Пользователь видит РАЗНЫЙ порядок плейлистов на разных платформах. Чинить в SQL-чтении + в API.

### 3. Запись в Rekordbox (Sync) — на Windows нет вовсе

Это большая работа. На macOS: `RekordboxWriter.swift` (оркестратор) + frozen-бинарь `rbdb-sync-helper`
(PyInstaller, pyrekordbox внутри — у пользователя нет ни pyrekordbox, ни sqlcipher3, поставить их
нельзя, поэтому самодостаточный бинарь). Обязательные части, каждая — из горького опыта:
- барьер «Rekordbox закрыт» (иначе он перезапишет базу поверх нас и потеряет правки);
- бэкап базы ДО записи;
- новые плейлисты добавляются НАВЕРХ списка (`Seq = 1`), а не в конец;
- верификация перечитыванием базы после записи;
- честные стадии прогресса (checking → backup → writing → verifying), которые отдаются в
  `GET /api/playlist/sync/status` — телефон их показывает, и они обязаны быть правдой, а не таймером.

### 4. Логи

На Windows нет ни ротации логов, ни access-log HTTP (peer IP, транспорт LAN/tunnel). Из-за этого
диагностический бандл «Report a problem» с Windows приходит без логов агента. Портировать
`AgentLogger.swift` и логирование в `HTTPServer.swift`.

### 5. Мелочи, которые тоже видит пользователь

- Кнопка «Update Now» в UI Windows зовёт `UpdateChecker.DownloadAndApply` напрямую, минуя
  `AgentUpdateService` ⇒ `GET /api/agent/update/status` во время UI-обновления врёт `idle`,
  и теоретически можно запустить две установки разом. Провести UI-кнопку через сервис.
- Windows не читает облачный конфиг `GET /api/similarity_config` вообще (движок захардкожен).
  После портирования рекомендаций он обязан его читать — иначе веса нельзя будет крутить из админки.
- Нет Authenticode-проверки распакованного `.exe` после обновления. На macOS есть
  `codesign --verify --deep --strict` + проверка TeamID. Подпись zip (ECDSA) на Windows есть,
  а вот подпись самого бинаря не проверяется.

## Как работать

- **Ничего не выдумывай.** Если чего-то на Windows нет и портировать честно не получается —
  скажи прямо и опиши, что мешает. Молча сломанная фича хуже отсутствующей: пользователь нажмёт
  кнопку, получит непонятную ошибку и решит, что продукт не работает.
  Пример из этой же истории: на Intel-маках агент объявлял, что умеет синк (проверял только бит
  «исполняемый», не архитектуру), кнопка светилась активной, а нажатие падало с «Bad CPU type in
  executable». Чинилось честной capability, а не попыткой запустить.
- **Capability обязана отражать РЕАЛЬНУЮ способность, а не намерение.** Если фича не работает —
  агент должен сказать об этом в capabilities, чтобы iOS не показывал кнопку.
- Windows-агент **не собирается на macOS** (нет `dotnet`, WinUI требует Windows). Проверяй
  синтаксис и логику вычиткой, а сборку — через CI (`RimeoAgent/.github/workflows/build.yml`,
  джоб `build-windows`). Дымовой тест на живой Windows всё равно потребуется — так и скажи в отчёте.
- **PARITY.md обновляй тем же коммитом.** Это правило проекта: фича, сделанная на одной платформе,
  обязана появиться строкой в матрице сразу, иначе разница снова начнёт копиться молча.
- Релиз агента = ДВА mac-ассета: `RimeoAgent_mac.zip` (имя захардкожено в `UpdateChecker` — убрать
  = тихо убить автообновление у всех) и `RimeoAgent.dmg` (для людей). Пуш билда — коммит + тег `v*`,
  без тега CI не стартует.

## Приёмка

Не «код написан», а:
1. Windows-агент отвечает на `POST /api/playlist/recommendations` тем же контрактом, что macOS.
2. На одной и той же библиотеке (можно тестовой) выдача Windows и macOS **совпадает по составу**
   (порядок может отличаться в пределах тай-брейков — объясни, где и почему).
3. `PARITY.md` после работы содержит ✅ там, где раньше было ❌, и ни одной строки, где статус
   не соответствует коду.
4. Честный список того, что осталось невыполненным и почему.
